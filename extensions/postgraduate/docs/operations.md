# 操作手册

## 安装前

1. 阅读 integration-audit，确认后端确有 Skill/MCP 扩展接口，使用与后端相同的工作目录和数据库配置。
2. 确认现有管理员、启用且支持工具的模型。不要为本扩展更改默认模型或其他 Agent。
3. 确认 MCP 解释器可导入锁定 SDK。新增依赖仅安装到独立 MCP venv；当前仓库虚拟环境已具备所需依赖，没有追加平台依赖。
4. 运行扩展测试。首次试运行应使用空业务库；不能把 tests fixture 当真实资料。
5. 现有 Docker 镜像缺接口时，停止安装，等待管理员确认平台升级。原入口 `backend/entrypoint.sh` 会运行已有 `alembic upgrade head`，不能把升级当成无 Schema 变更的扩展注册。

## 备份与恢复

- 安装注册前，对主库做一致性备份。SQLite 应使用 `sqlite3.Connection.backup` 或停写快照，不能只复制正在运行且有 WAL 的单个 .db 文件。
- 部署升级前保留旧镜像 ID、原 compose、迁移版本和完整 `/data` 备份。回滚旧镜像时必须同时恢复匹配的数据库备份；不在本扩展中实现公共 Schema 降级。
- 独立业务卷包含 `university_data.sqlite3`、`exam_knowledge.sqlite3`、`notification.sqlite3`、`research_requests.sqlite3` 及 documents/exports/models 等目录。逐库在线备份不能保证跨库同一业务时点；需要一致整体快照时先停用本扩展两个 Agent 并等待执行结束。
- 恢复到单独目录验证完整性，再通过管理员配置切换。通知库必须一并恢复，丢失幂等历史可能导致人工重发；`uncertain` 记录先人工对账。
- 不提交备份、原始题库、密钥或用户资料到 Git。

## 启停与故障

- 管理台停用 Agent：停止新运行；已有执行按平台行为处理，必要时在执行页取消。
- 停用 MCP Server：后续实际调用失败，不会自动换别的工具或绕过。
- 停用 Skill：绑定该 Skill 的实例解析失败，其他实例不受影响。
- 无搜索/地图 Key：报告缺口；可以继续处理管理员已导入的合法资料。
- 无招生/大纲数据：明确 empty/unavailable，不补造来源。
- 无模型：ML 固定 unavailable；LLM 模型与招生预测模型是不同配置。
- 注册失败：服务层可能已提交前面部分注册；核对名称/归属/路径后原命令重试。不同路径/解释器/env 的同名注册不会被自动覆盖。
- 外发失败：读取 delivery 状态；不确定状态人工核对。网络真实发送未在本次验收中执行。
- 查看执行详情与工具执行记录追踪调用；通知业务库记录幂等键、摘要与状态，不存正文凭据；research 配额库仅存 host/provider 与时间。平台执行记录仍包含业务输入/输出，按平台既有访问控制和保留策略管理。

## 卸载

先取消/等待两个实例的活动执行，运行 `manage.py uninstall`，核对返回结果，再去掉独立挂载。它不删除业务卷或历史执行，不修改原有 Agent、默认工具或模型。外部 Agent/Workflow 仍引用本扩展时必须先处理引用；共享提示词保留并在结果中列出。不要使用删除主库或删除整个 `/data` 的方式卸载。

## 发布状态

仓库代码与临时库验收不代表当前 Docker 服务已经更新。实际服务安装需单独记录使用镜像、迁移版本、两个 Agent ID、发布版本及 MCP ping 结果。未获得升级确认时，交付状态是“扩展可运行、生产未接入”。
